## Procedimento implementado

Arquivos: `app/core/backend_lifecycle.py`, `app/controlled_server.py`, `scripts/backend_control.py`, `scripts/backend.sh`, e integração nos scripts oficiais Start/Stop PowerShell. Os wrappers CMD continuam repassando argumentos.

- O controle existe somente quando iniciado por `app.controlled_server`.
- Escuta em loopback, desativa confiança em proxy headers, exige token aleatório e rejeita Origin de navegador. O token fica no diretório privado dos dados; não é impresso ou colocado na linha de comando. Não compartilhar o diretório `backend-control` nem expô-lo como arquivos estáticos.
- Antes da parada: identidade da instância, API, fila, jobs, pipeline, workers registrados, guitarra, retime/karaokê, relocação e requisições HTTP em andamento.
- Se estiver ocupado, retorna 409 e continua atendendo normalmente. Após aceitar, bloqueia novas requisições e solicita saída normal do Uvicorn via `should_exit`.
- O controlador espera a porta ficar livre. Timeout não força encerramento e não inicia substituto.
- Início recusa porta ocupada, runtime inexistente ou divergência de `jobs_dir`. Controladores concorrentes sobre os mesmos dados são serializados por arquivo exclusivo; não há remoção automática de lock obsoleto.
- Novo processo usa o venv do runtime, cwd do worktree e dados explicitamente informados. Os logs recebem um nome por instância.
- O script oficial Stop não contém mais `taskkill /T /F`. O Start recusa um servidor já existente; para reiniciar, usar `restart`.
- Não iniciar outra porta com a biblioteca principal enquanto o legado estiver ativo. Os dados da 8160 são exclusivamente sintéticos.

**Não executar uma parada forçada para cumprir este pré-requisito.** Como o terminal original não está acessível, o bootstrap continua dependente de recuperar o host que iniciou o servidor ou de outra intervenção operacional normal verificada.
